# v0.37 Durability Model

v0.37 changes the persistence model for consequential execution safety.

Old model:

```text
a turn's events are buffered and appended atomically at the end
```

New model:

```text
ordinary turn work may remain buffered, but consequential external execution crosses explicit durable safety checkpoints
```

## Expected-Sequence Append

`SessionStore.append(sessionId, drafts, { expectedSeq })` is an optimistic compare-and-append
operation. The store appends the drafts only when the current durable session sequence exactly
equals `expectedSeq`; otherwise it throws `SessionConcurrencyConflictError` with code
`session_concurrency_conflict`.

The comparison and append are one atomic store operation. Sequence numbers remain monotonic and
gapless. A runtime never silently appends a stale turn after another writer has advanced the same
session.

## External Execution Checkpoints

For tools declared as `external_side_effect`, dispatch order is:

```text
validate input
authorize
resolve exact confirmation when required
compute the stable action identity and idempotency key
durably persist ToolExecutionStarted with expected-sequence protection
call the external executor only after that durable write succeeds
durably persist ToolExecutionSucceeded, ToolExecutionFailed, or ToolExecutionOutcomeUnknown
continue ordinary model/harness work
```

`ToolExecutionStarted` is a safety boundary, not proof that the remote action succeeded or even ran.
The terminal event is the authoritative durable outcome.

## Interrupted Executions

Replay/project detects an external `ToolExecutionStarted` without a matching terminal event by
`requestId`, `actionKey`, and `idempotencyKey`. That state is represented as
`SessionState.unresolvedExternalExecution`.

An unresolved external execution is treated like `outcome_unknown` for authorization purposes:
Agent_SDK does not infer success, does not infer definite failure, and does not automatically
redispatch the same action. While a session contains an unresolved external execution, further
external side-effect dispatch is blocked for that session.

## Concurrency Conflicts

Same-session expected-sequence conflicts stop the current turn conservatively. The stale runtime
does not retry the model plan, does not retry a confirmed action, does not call the external
executor whose start checkpoint lost CAS, and does not append its buffered turn.

The caller may issue a new turn after reloading current session truth.

## Snapshots And Idempotency

Snapshots remain caches of the event projection. They never define truth and must not claim events
that were not durably stored.

Runtime-owned idempotency keys remain stable and should still be passed to remote APIs that support
idempotency. In v0.37, idempotency is defense in depth, not the sole safety mechanism.

v0.37 does not claim exactly-once remote execution. The guarantee is narrower: Agent_SDK prevents
automatic duplicate dispatch after a durable execution-start boundary and conservatively treats
ambiguous crash windows as outcome unknown. Remote API idempotency provides an additional layer of
protection when available.
