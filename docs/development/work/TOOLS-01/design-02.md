# Design 02 — TOOLS-01 corpus and verification composition

## Mechanism

Continue the released packet on `codex/tools-01`. Keep design 01's immutable Git input and
temporary-process execution. Add a maintained adoption manifest, separate from the pinned audit
catalogs. Each origin has an explicit disposition and rationale: a runnable case or existing-suite
mapping, a duplicate with a resolved destination, or non-executable evidence with its source and
reason. Unresolved extraction remains pending and prevents corpus completion. Counts of origins,
tests, mutants and policy questions are separate. A source digest proves provenance, not the
semantic adequacy of a mapping; the latter remains inspectable review work.

Extend the registry to run ordinary counterexamples as well as mutations. Name the profile and
observable assertion. Held defects use witness cases which assert the recorded failure, explicitly
attributed to their correction owner; their successful reproduction does not release a claim hold.
Global replacement probes run in fresh children. Preserve access form, stage and environment in
their cases, including assignment, defineProperty, global declaration and pre-pin declaration.
Closed-by-reading mutants carry their argument and never contribute executable kill counts.

Adopt the existing complete-decision fault oracle and its negative controls without changing its
legal decisions or phase-specific exceptions. Register comparison mutations in the same runner.
An adapter must distinguish an actual named assertion failure from syntax/import/setup errors,
check the passing control, and establish that the intended comparison was reached. No nonzero
process exit alone establishes a kill. Existing dependencies required by these fixtures are copied
only through an explicit version/content-checked adapter, with the observed identity reported.
No package is added and no historical runner executes against the user's checkout.

Compose the packet's required checks into one clean-C command. Read its specification at C,
require HEAD and tracked/untracked source to match C, run the declared commands, and report
versions, argv, exits and counts/skips. Verify inventory, maintained corpus, mutation controls,
typecheck, repository tests and standalone Kernel sweeps. A verification run reports evidence,
not independent acceptance. Candidate C/H verification remains a separate immutable wrapper check.

## Why each criterion closes

| Criterion | Mechanism and check |
|---|---|
| F1 | Keep exact immutable B/C/H and attachment checks; add regressions for any discovered false acceptance. The verifier does not authenticate human decisions. |
| F2 | Replay every pinned source before resolving adoption. Origin IDs are a finite exact set; missing, duplicate and unknown mappings fail. No filename-based recommendation becomes adoption automatically. |
| F3 | Explicit case/assertion identity, passing control, unique mutation site and independent failure observation. Negative fixtures cover every result category and oracle false positives. |
| F4 | Fresh temporary source trees and processes for each execution, bounded output/time, checked dependencies and source-preservation assertions. This is not hostile-code containment. |
| F5 | Separate provenance completeness, mapping completeness, execution results and policy holds. Pending mappings, failed witnesses or setup errors cannot produce full-corpus completion. |
| F6 | Maintained usage/schema documentation, exact-C report and external handover. No Layer-3 rule changes: the governing evidence owner already distinguishes observation from acceptance. |
| P1 | Inspect each artifact and prose locator in context, retain a per-origin semantic mapping, port distinct missing assertions and preserve the complete-decision oracle. Duplicates resolve to maintained coverage; non-executable evidence explains why execution is not claimed. |
| P2 | One clean-C composition executes the declared current profile, including negative controls of the tooling and oracle. Cumulative self-review checks the mappings and interactions. Independent acceptance is reserved for the owner's separate reviewer. |

## Accepted designs relied on

- 006/008/012: fit for immutable identities, independent review and accumulated counterexamples.
  No process amendment is proposed.
- Foundation verifier/runner: fit as a starting point; its explicit observation protocol needs
  adapters and mapping validation before broad adoption. Its single case is not corpus coverage.
- Audit inventory: fit as provenance, unfit as automatic semantic classification. Review source
  content rather than adopting filename recommendations.
- Complete-decision oracle: fit for its declared in-process fault profile, including its apply
  windows and independent grant/position probes. Do not claim durability or general fault atomicity.
- Existing binding tests and analyzer: retain as current-profile evidence with their known limits.
  The audit's CORE/Proxy/realm drafts remain unadopted; V-D1, classification and V-ENV holds remain.

## Corpus

All 208 artifact/fence origins, 1,333 prose origins and eight final-review additions remain in the
intake. Preserve review-12/revision-9 oracle counterexamples, prior surviving mutants and the
review-03 realm/freeze witnesses. Add maintained tests for each tooling defect found in this work,
with implementer provenance rather than attributing it to a prior reviewer. No sealed evidence,
production Kernel module, hostile suite or analyzer is retired.

## Questions

No new Kernel decision is needed for this design. The owner's present instruction authorizes
continuing evidence tooling while Claude researches; findings may inform later implementation
choices but do not authorize semantics. PROXY-01, bytes-core adoption, wrapper packaging and realm
policy remain with their existing owners. If extraction reveals that closing a required case
requires changing accepted behavior, a dependency, packet scope or an oracle's legal outcomes,
record the concrete conflict and ask before dependent implementation. This note is implementer
rationale, not independent design acceptance.
