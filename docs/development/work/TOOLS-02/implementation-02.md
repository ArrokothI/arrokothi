**T2-R1-READ-01 → disposition: fixed in C.** The cause was the trace mechanism, not the probe's member:
- the TOOLS-01 tracer kept each call's first argument only, so `{ recursive: true }` was lost;
- `listing()` modelled every listing as immediate children.

The fix follows design 04 §1.
- **Record.** A `tree` read stands for its directory's listing and every subtree's listing. In the record (at C),
  each implied listing is classed like any listing. Fixture listings enter with their typed entries; every other
  listing is recorded by its walk root, so owner choice 01's stability for unrelated additions holds.
- **Pin comparison.** It expands over both revisions' directories, so a fixture subtree present only at the pin
  still counts.
- **Glob and cp.** These reads have no represented dependency identity, so they refuse their file with a stated
  reason.

**Brief 02's questions** are answered in design 04 §§1–3:
- Q1 and Q2: the supported modes and their path through capture, classification, identity, reasons, aggregation and
  regeneration;
- Q3: the nearby forms, each with a control or a stated bound;
- Q4: no owner amendment. The change makes the code match design 05 rule 5's "directory entries" and owner
  choice 01's "any fixture read", and it only removes preservation.
