**The recurring mechanism, removed.** Review 02's root cause was that each traced call was reduced to a path and a
kind before anyone checked that this represented the call, so an unfit row was dropped silently. Now `admit` decides
every raw row first, and refusal is the default:
- a row reaches `read` only through a matrix entry: a path first argument, an admitted second-argument form, and
  admitted option keys;
- it reaches `outside` only for a path outside the repository, under `node_modules`, or in the static import closure;
- everything else is `refused`, and any refused row refuses its file:
  - `glob` in every form, and `cp` from inside the repository;
  - descriptors, file handles and unlisted operations;
  - unlisted option keys, such as `createReadStream`'s `fd` and `fs`;
  - aliased paths.

**Findings:**
- **T2-R2-PATTERN-01, fixed.** An array glob is refused before any path filter. So are callback and promise globs.
- **T2-R2-READ-01, fixed under owner choice 04.** A recursive listing that crosses a tracked symlink refuses, at C and
  at the pin. The same rule covers `readdir`, which descends links, and `opendir`, which does not, and no target is
  followed.

**Design check 05:**
- **D05-CHK-1:** `covered` is withdrawn. Descriptors and handles refuse; options are admitted only by key.
- **D05-CHK-2:** the path is walked component by component before normalization, starting from the original text and
  working directory. A tracked symlink refuses, so `tests/fixtures/jump/../actual.txt` no longer resolves to the
  decoy. Untracked links, such as system prefixes and `node_modules` workspace links, are followed.
- **D05-CHK-3:** a read whose path or any ancestor was a tracked symlink at the pin refuses that origin's members. This
  includes the equal-blob link→file case.
- **§6 answers adopted:**

  - file existence identity is `(Git mode, blob ID)`, with directories type-only. It claims Git-recorded content,
