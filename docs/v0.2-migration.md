# Migrating to Agent SDK v0.2

v0.2 makes retrieval explicit, adds a structured turn-planning seam, and replaces heuristic
side-effect authority with typed source policies. The runtime and session model remain compatible
with the v0 architecture: definitions are serializable, executors and providers are injected, and
sessions reconstruct from events plus optional snapshots.

## Dependencies

`@agent-sdk/core` now has two narrow runtime dependencies:

- `@langchain/core` for `Document` and `BaseRetriever`;
- `@langchain/textsplitters` for `RecursiveCharacterTextSplitter`.

They are implementation details of local document Knowledge. No LangChain type crosses the public
Knowledge boundary, and LangChain is not used for orchestration, agents, tools, memory, or Flow.

## Definition changes

### Planning

Planning is optional configuration on `AgentDefinition`:

```ts
planning: {
  mode: "llm", // "llm" | "deterministic" | "hybrid"
  model: { providerId: "cheap", model: "small-planner" },
}
```

If omitted, rich agents use `llm` planning and the main model policy/provider. An
`AgentRuntimeConfig.planningModel` can inject a separate provider implementation.

### Knowledge descriptions and chunking

Add a concise `description` to each knowledge source so the planner can select logical sources
without seeing their contents. Document chunking is now configured as:

```ts
source: {
  id: "policies",
  kind: "document",
  title: "Property policies",
  description: "Building rules, amenities, and pet policies.",
  text,
  chunking: { chunkSize: 1000, chunkOverlap: 200 },
}
```

The defaults are 1000 characters and 200 characters. Replace the old `chunkChars` field with the
`chunking` object. Remove `autoRetrieve`; the planner now emits explicit retrieval requests.

### Named rules

Legacy string rules remain accepted and are treated as non-overridable invariants. New definitions
should use named rules:

```ts
globalRules: [
  { id: "truthful-actions", kind: "invariant", text: "Never claim an action succeeded unless ToolResult says so." },
  { id: "concise", kind: "default", text: "Keep responses concise." },
]
```

A phase may list `overrideRuleIds`, but only for `default` rules. Overriding an invariant or an
unknown ID is a definition error.

### Resource limits

`defineAgent` fills these defaults when omitted:

```ts
policies: {
  maxRetrievalRequests: 4,
  maxDocumentChunks: 4,
  maxRecordRows: 20,
  maxKnowledgeChars: 12000,
}
```

### Consequential tool arguments

Every declared input argument of an `external_side_effect` tool now needs an explicit policy:

```ts
argumentPolicies: {
  contact_email: {
    kind: "authoritative_value",
    sources: ["memory.contact_email", "host_context.account_email"],
  },
  summary: { kind: "model_composed" },
}
```

Supported source paths are `memory.<key>`, `host_context.<key>`, and `tool_fact.<key>`. Authoritative
values are compared using typed whole-value equality; arrays are compared structurally. Substring
matches and working notes cannot grant authority. Confirmation remains an additional gate and never
bypasses provenance.

## Runtime wiring

`AgentRuntime` now consumes the provider-neutral `KnowledgeProvider` interface:

```ts
const knowledge = new KnowledgeIndex(definition.knowledge);

const runtime = new AgentRuntime({
  definition,
  sessions,
  model: responseModel,
  planningModel, // optional; defaults to responseModel
  tools,
  knowledge,
});
```

`KnowledgeIndex` is the default local implementation. Document requests use LangChain splitting
and retriever plumbing with SDK-local lexical ranking. Record requests use the deterministic SDK
query engine and never pass through document RAG.

## Compiler changes

Remove calls to `compileWithRetrieval`. Retrieval now runs before compilation:

```ts
const compiled = compileContext({
  definition,
  state,
  retrievedKnowledge,
  now,
});
```

`compileContext` is synchronous and cannot query a provider or index. Harness performs this order:

```text
Interpret + Plan -> validate/execute RetrievalRequest[] -> KnowledgeResult[] -> compileContext
```

Use `compilePlannerContext` only when implementing a Harness planning strategy. It exposes a concise
source catalog, not source contents or restricted host data.

## Knowledge API changes

Replace the old open-ended `KnowledgeQuery`/implicit retrieval surface with:

- `DocumentSearchRequest` for one logical document source;
- `RecordQueryRequest` for schema-validated filters, sorting, and limits;
- `RetrievalRequest` as their discriminated union;
- `KnowledgeResult` as the evidence passed to the compiler;
- `KnowledgeProvider.catalog`, `.retrieve`, and `.queryRecords`.

The planner selects the source and writes a standalone document query. Runtime validates source
existence, source kind, phase scope, non-empty query, filter/sort fields and operators, typed values,
and all configured limits before evidence reaches the response model.

## Memory and events

Memory now records write mechanism separately from provenance:

```ts
writeMechanism: "planner_proposal" | "runtime_observation"
provenance: {
  kind: "user_claimed" | "tool_verified" | "host_provided" | "model_inferred"
  sourceEventIds: string[]
  sourceName?: string
}
```

Planner-extracted user facts cite the exact `UserMessageReceived` event. Tool-written facts cite
`ToolExecutionSucceeded`; accepted host context cites `HostContextObserved`. Model inference is
advisory unless a field explicitly opts into authoritative inferred values.

New event types are `TurnPlanCreated`, `RetrievalRequestRejected`, and `KnowledgeRetrieved`. The last
stores request and compact result metadata (IDs, scores, counts), not raw document contents.

## Removed behavior

v0.2 has no parallel compatibility path for hidden auto-retrieval. It also does not introduce
embeddings, vector stores, hosted retrieval, LangGraph, LangChain Agents, multi-query RAG,
reranking, arbitrary SQL, Skills, or multi-agent workers.

## Suggested migration order

1. Add source descriptions and replace document `chunkChars` with `chunking`.
2. Add the four retrieval resource limits or let `defineAgent` apply defaults.
3. Convert prompt rules to named rules where phase overrides are needed.
4. Add `argumentPolicies` to every external-side-effect tool.
5. Inject `KnowledgeIndex` through `AgentRuntime.knowledge`.
6. Replace custom compiler retrieval with planned `KnowledgeResult[]`.
7. Update trace/UI consumers for the three new events and memory provenance shape.
8. Run `npm run typecheck` and `npm test`.
