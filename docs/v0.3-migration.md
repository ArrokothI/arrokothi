# Migrating to Agent SDK v0.3

v0.3 adds iterative execution without removing the v0.2 workflow Harness. Existing definitions and
`AgentRuntime` wiring continue to use `TwoPassHarness` unless an application injects another
Harness (or the Studio definition selects one).

## Compatibility summary

- `AgentHarness` remains the public execution seam.
- `TwoPassHarness` remains supported and is still the runtime default.
- `TurnPlan` remains exported as an alias of `PreflightPlan`.
- Gemini remains a provider-neutral `ModelProvider` outside core.
- Existing document/record `KnowledgeIndex` construction remains valid.
- Existing Tool authorization, confirmation, idempotency, Flow, events, and snapshots remain valid.

## Choose a Harness

Workflow-style behavior needs no code change:

```ts
new AgentRuntime({ definition, sessions, model, tools, knowledge });
```

For iterative provider-neutral execution:

```ts
new AgentRuntime({
  definition,
  sessions,
  model, // GeminiProvider or any ModelProvider
  tools,
  knowledge,
  harness: new NativeAgentHarness(),
});
```

For Claude Agent SDK, install/use the optional workspace package:

```ts
import { ClaudeAgentHarness } from "@agent-sdk/provider-claude-agent";

new AgentRuntime({
  definition,
  sessions,
  model: planningProvider,
  tools,
  knowledge,
  harness: new ClaudeAgentHarness({ executionContextPolicy: "fresh_each_turn" }),
});
```

The runtime still needs a neutral model provider for optional PreflightPlan generation. The Claude
Harness itself uses the Claude SDK adapter for its inner execution.

## New deterministic policies

`defineAgent()` supplies defaults, so most definitions require no edit:

```ts
policies: {
  maxAgentIterations: 8,
  maxKnowledgeCallsPerTurn: 12,
  maxActionRequestsPerTurn: 4,
  maxParallelReadCalls: 4,
}
```

Definitions deserialized through `defineAgent()` receive these defaults. Hand-constructed
`AgentDefinition` objects should add them or be migrated through `defineAgent`.

## Preflight terminology

Use `PreflightPlan` in new code and documentation. Its shape is unchanged from v0.2 `TurnPlan` and
the old name remains an alias. It establishes memory, notes, signals, and optional initial
retrieval. It is not the autonomous inner-loop plan.

## Web Knowledge

Add a `web_search` source and inject a `WebSearchProvider` into the default index:

```ts
const definition = defineAgent({
  // ...
  knowledge: [{
    source: {
      id: "company_site",
      kind: "web_search",
      title: "Company website",
      description: "Official company information.",
      allowedDomains: ["example.com"],
      maxResults: 5,
    },
  }],
});

const knowledge = new KnowledgeIndex(definition.knowledge, { webSearch });
```

With no provider, document and record Knowledge continue to work; a requested web source fails
explicitly with `web_search_unavailable`.

## Out-of-band Host Context

Hosts may now observe navigation or selection state without a model call:

```ts
await runtime.observeHostContext({
  sessionId,
  hostContext: {
    current_page: "/products/b",
    selected_product_id: "b",
  },
});
```

This operation does not emit a reply. Continue using `runTurn({ hostContext })` when context and a
user message should be accepted atomically.

## Events and trace consumers

Trace UIs should accept these additive families:

- `AgentIterationStarted`;
- `DelegationRequested`;
- `DelegationRejected`;
- `DelegationCompleted`;
- `AgentIterationCompleted`.

Reducers that ignore unknown events remain replay-safe. No hidden reasoning text is persisted.

## Studio

Studio definitions can select TwoPass, Native Agent, or Claude Agent. It can author document,
record, public-web, and company-domain sources. `Update context only` calls the development
`POST /api/sessions/:id/context` route without starting a turn.

For optional live integrations:

```bash
ANTHROPIC_API_KEY=... npm run studio
STUDIO_WEB_SEARCH_ENDPOINT=https://your-provider.example/search npm run studio
```

The web endpoint accepts a provider-neutral JSON search request and returns `{ query, results }`.

## Deferred features

Do not migrate Skills, subagents, teams, MCP, cross-turn Claude resume, proactive context triggers,
or a browser SDK into v0.3. Those remain explicit v0.4 hypotheses.
