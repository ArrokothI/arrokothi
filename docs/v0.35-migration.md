# Migrating to Agent SDK v0.35

v0.35 consolidates external-turn orchestration around one primary `AgentHarness` and moves the
canonical temporary agent loop behind a provider-neutral `AgentLoopEngine` interface. Strands is an
integration dependency, not an application-state dependency.

## Dependency versions

The v0.35 Strands package pins the exact versions validated by this repository:

```json
{
  "@strands-agents/sdk": "1.14.0",
  "@google/genai": "2.6.0"
}
```

`@google/genai` is a direct peer required by Strands' Google model subpath. Credentials remain
outside `AgentDefinition` and enter through application wiring.

## Replace multiple Harness choices

New agentic construction:

```ts
import { AgentHarness, AgentRuntime } from "@agent-sdk/core";
import { createStrandsGeminiEngine } from "@agent-sdk/integration-strands";

const runtime = new AgentRuntime({
  definition,
  sessions,
  model: preflightModel,
  tools,
  knowledge,
  harness: new AgentHarness({
    engine: createStrandsGeminiEngine({ apiKey: process.env.GEMINI_API_KEY }),
  }),
});
```

Bounded workflow construction:

```ts
harness: new AgentHarness({ strategy: "workflow" })
```

`AgentRuntime` uses that workflow strategy when `harness` is omitted, preserving the old bounded
default without making `TwoPassHarness` the public architectural center.

## Definition changes

Use these execution values for new definitions:

```ts
execution: {
  harness: "agentic", // or "workflow"
  executionContextPolicy: "fresh_each_turn",
}
```

The values `two_pass`, `native_agent`, and `claude_agent` still parse for compatibility but point to
legacy paths.

Rules may now state which semantic work receives them:

```ts
globalRules: [
  { id: "plan", kind: "invariant", scope: "planner", text: "Prefer first-party evidence." },
  { id: "answer", kind: "invariant", scope: "response", text: "Cite the authoritative result." },
  { id: "safety", kind: "invariant", scope: "both", text: "Never claim an unexecuted action." },
]
```

Legacy string rules are treated as `scope: "both"`.

Set `planning.extractWorkingNotes: false` only when the definition genuinely needs no semantic
Working Notes. Together with zero Memory fields and zero Flow signals, this can make Preflight
structurally unnecessary in agentic mode.

## Preflight behavior changed

In the primary agentic path, Preflight may propose only:

- user-established Structured Memory updates;
- ephemeral Working Notes;
- coarse Flow/routing signals.

Retrieval plans and task decomposition have moved to the iterative loop. The agentic planner sees
no knowledge source catalog and its accepted `retrievalRequests` are forced empty. Workflow mode
keeps compatibility retrieval planning.

Preflight is skipped only when the definition has no Memory fields, no available Flow signals,
Working Note extraction is disabled, and there is no compatible workflow retrieval output. The
decision is structural; it does not inspect user phrases with regexes or keyword lists.

## Engine and intervention boundary

Core defines `AgentLoopEngine`, `AgentLoopInput`, `RuntimeDecision`, and neutral trace events. The
Strands package implements that contract and adapts Agent_SDK decisions as follows:

| Agent_SDK decision | Strands intervention behavior |
| --- | --- |
| `proceed` | continue |
| `deny` | deny the current request |
| `guide` | feed deterministic corrective guidance into the same loop |
| `confirm` | interrupt/pause while Agent_SDK's `PendingAction` remains authoritative |
| `transform` | modify input, then run Gateway validation/hash/confirmation on the new payload |

Hooks observe invocation/model/tool lifecycle. They do not grant authority. Every Knowledge or Tool
request still crosses `CapabilityGateway`, and no Strands tool callback can perform a side effect
without a prior authoritative Gateway result.

## Context and persistence

The new boundary separates three mechanisms:

- `ContextCompiler` builds the authoritative initial context from Agent_SDK state.
- Strands `ConversationManager` reduces only temporary inner-loop history when needed.
- Agent_SDK Durable Session remains the reconstructable business truth across external turns.

One fresh Strands `Agent` and one mutable `InvocationState` are created per external user turn.
Restricted/runtime-only Host Context can travel in InvocationState for adapters, but is never added
to model messages. InvocationState is not persisted wholesale and cross-turn Strands session resume
is not part of v0.35.

## Call accounting

`RunTurnResult.metrics` now reports:

```ts
{
  preflightModelCalls,
  agentLoopModelCalls,
  conversationSummaryModelCalls,
  guideRetryModelCalls,
  totalModelCalls,
}
```

A structurally trivial direct answer is normally one agent-loop call. A semantic-state turn is
normally one Preflight call plus one or more loop calls. Tool paths add a loop call after each
observation. Guide retries and conversation summaries are counted separately and included in the
total.

## Compatibility and deprecation

- `TwoPassHarness`: retained and deprecated; use `AgentHarness({ strategy: "workflow" })`.
- `NativeAgentHarness`: retained and deprecated as an offline/reference implementation.
- `ClaudeAgentHarness`: retained in its provider package as an experimental compatibility path.
- `ReferenceLoopEngine`: retained for deterministic examples/tests, not the production canonical
  agentic engine.

Do not remove compatibility code until parity and production confidence justify it. v0.35 does not
add Skills, subagents, MCP, Strands Graph/Workflow/Swarm, cross-turn Strands resume, or a semantic
LLM rule judge.

## P01/P02 builds

The standalone `examples/p01-craig` and `examples/p02-estate` definitions were rebuilt from their
original requirements and product data. They do not import the references' bespoke chat/runtime
implementations. Historical benchmark artifacts remain present; this release does not claim a new
Agent_SDK-versus-other-builder comparison.
